## 任务：导入测试商品

### 做法（已验证可复用）
- 新建种子类 `database/seeders/TestProductsSeeder.php`，用 `ProductRepository::create()`（仅 type/attribute_family_id/sku）+ `ProductRepository::update()`（属性值 + channels/categories/inventories）创建 simple 商品

- 创建后必须跑索引：`php artisan indexer:index --type=flat --type=price --type=inventory --mode=full`，否则 product_flat 为空、前台看不到商品

### 关键坑（重要）
- **`db:seed` 会全局 `Model::unguard()`**，导致 `$product->update($data)` 把 name/price/locale 等当真实列写入而报 "Unknown column"。解决：种子里 `Model::reguard()`（与 tinker 的 guarded 行为一致），非属性列会被跳过，属性值由 attributeValueRepository 处理
- 多语言属性值必须传**标量**（如 `'name'=>'xxx'`），不能传 `['en'=>'xxx']` 数组（否则 "Array to string conversion"）；`locale`/`channel` 不要放进 update 的 $data，saveValues 会自动用默认 en/default
- 商品/分类的 `url_rewrites` 仅在后台 HTTP 流程（有 request）时由 Marketing 监听器生成；用仓库直接创建不会生成，但前台 `ProductsCategoriesProxyController` 是按 slug 直接 `findBySlug` 解析的，所以 `/tb-001` 仍可直接访问，url_rewrite 缺失只影响 SEO 重定向
- 前台商品卡片/列表价格是经 storefront API 的 `price_html` 字段（服务端生成），游客返回 "Please log in to view price" + `login-prompt-link`，登录可见功能在列表/详情均生效
- categories 表是嵌套集，插入需 `_lft`/`_rgt`；分类-渠道关联表名为 `channel_categories`（不是 category_channels）；分类多语言名在 `category_translations`
